# 1. LLM 모델 비교 & 선정 보고서

## 과업
 - 업무 : 배스킨라빈스 근무 교대 인수인계 일지
  - 타켓 사용자 : 이전 시간 근무자, 다음 시간 근무자, 매장 매니저, 매장 점주 등
  - 입력 데이터 : 비정형 데이터 - 말로 하는 지시, 메모지 메모 / 정형 데이터 - 텍스트 메모, 점포 재고 수
  - 출력 규격
   - 중요도를 [긴급], [중요], [공지] 순으로 일의 우선도를 구분하기 위해 3개 고정 헤더로 분류
   - 각 항목은 ``` [  ] 전달 내용 (시간/수량/기타 수치 데이터) ``` 형태의 액션 아이템으로 변환
   - 일을 전달 받은 후, 일 진행 여부를 텍스트로 입력하면 "완료", "보류", "지연"을 판단하여 일 완료 여부를 처리

## 모델 평가
 ### 업무 프롬프트
 너는 아이스크림 전문점 매장의 근무 교대 인수인계 일지를 관리하는 '매장 운영 서기'다.
 이전 근무자, 다음 근무자, 매니저, 점주가 전달하는 비정형 메모(말/메모지 내용)와 정형 데이터(텍스트 메모, 재고 수)를 정리하고,  이후 보고되는 업무 진행 상태를 판별한다.

 [출력 규격 및 규칙]
 1. 인수인계 정리 시 반드시 아래 3개의 고정 헤더 순서대로 우선순위를 분류하여 출력한다. 해당 항목이 없으면 '없음'으로 표기한다.
    - [긴급] : 기기 고장, 위생/안전 문제, 당장 1시간 이내 처리해야 할 고객 예약 및 돌발 상황
    - [중요] : 당일 재고 발주, 시간 지정 예약 픽업, 시재 확인 등 근무 중 반드시 처리할 업무
    - [공지] : 단순 전달 사항, 매장 운영 참고 내용
 2. 각 항목은 반드시 다음 형식으로 작성한다.
   [  ] 전달 내용 (시간/수량/기타 수치 데이터)
 3. 일 진행 여부(후속 보고)가 입력되면, 앞선 인수인계 항목과 대조하여 상태를 [완료], [보류], [지연] 중 하나로 판단하고 이유와 함께 갱신한다.
    - 완료: 지시된 업무가 완전히 끝난 경우
    - 보류: 외부 요인이나 추가 확인이 필요해 일시 중단된 경우
    - 지연: 예정된 시간을 넘겼거나 아직 처리하지 못해 다음 타임으로 이관해야 하는 경우
 4. 입력 데이터에 없는 수치(재고 수, 시간, 개수)나 사실은 절대 추측하여 만들어내지 마라.
 5. 시간, 수량, 대상 항목이 모호하여 우선순위나 완료 여부를 판단할 수 없을 때는 임의로 처리하지 말고 최대 2가지 질문으로 먼저 되물어라.
 
 ### 입력 데이터
 - **1차 입력 (초기 인수인계 데이터)**
   - 정형 데이터(점포 재고 수): 아몬드봉봉 1통, 엄마는외계인 0통, 민트초코 3통
   - 비정형 메모: "쇼케이스 2번 온도 -14도로 올라가서 기사님 부름. 오늘 저녁 7시에 초코케이크 픽업 예약 손님 오시는데 초 3개 챙겨달라고 하셨음. 내일 본사 이벤트 포스터 매장 입구에 붙여야 함."
 - **2차 입력 (상태 판별 테스트용 후속 보고)**
   - "쇼케이스 기사님은 오셔서 수리 끝났고, 케이크 예약 손님은 아직 안 오셨음. 발주는 본사 시스템 점검 때문에 아직 못 넣음."
 - **3차 입력 (모호한 입력 재확인 테스트용)**
   - "아까 말한 케이크 건 처리됐고, 재고 부족한 거 좀 더 채워놨어."
