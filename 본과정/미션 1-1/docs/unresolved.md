# 4. 미해결 기록 (unresolved.md)

## [미해결 1] 구두로 전달된 연속적인 비정형 메모에서 '이미 완료된 일'과 '할 일' 자동 분리하기

### 시도한 프롬프트 원문
```text
너는 아이스크림 전문점 매장의 근무 교대 인수인계 일지를 관리하는 '매장 운영 서기'다.
근무자가 두서없이 입력한 메모에서 이미 처리가 끝난 일은 [완료]로 분류하고, 다음 근무자가 해야 할 일만 [  ]로 구분해서 [긴급], [중요], [공지] 순서대로 정리해 줘.

입력 메모:
"아까 오전에 쇼케이스 1번 성에 낀 거 다 제거해 놨고, 2번은 온도 올라가서 기사 부름. 그리고 어제 들어온 케이크 박스는 창고에 정리 끝났는데, 오늘 7시 초코케이크 예약 초 3개는 아직 안 챙겨놨어."
```

### 받은 결과
- 이미 완료된 작업(`쇼케이스 1번 성에 제거`, `케이크 박스 창고 정리`)까지 다음 근무자가 처리해야 할 `[긴급]` 또는 `[공지]` 할 일 목록에 섞어 넣거나, 단순 완료 기록을 다시 확인해야 할 업무로 중복 분류하는 현상이 반복됨.

### 막힌 이유 (직접 작성)
- 한국어 구어체 메모에서는 과거형(`~해 놨고`, `~끝났는데`)과 진행형(`~부름`, `~안 챙겨놨어`)이 한 문장 안에 섞여 들어오는데, 모델이 '이미 끝난 보고'와 '다음 근무자가 이어받아야 할 미완료 업무'의 경계를 명확히 분리하지 못했다. 프롬프트에 시제 구분 규칙을 추가해도 문맥이 길어지면 완료된 일까지 체크리스트에 올려버려, 결국 사람이 입력 전에 완료된 건은 빼고 적어야 하는 한계가 남아 미해결로 기록했다.

## [미해결 2] 이전 대화 턴의 재고 수량과 후속 보충 수량을 자동 합산하여 현재 재고 갱신하기

### 시도한 프롬프트 원문
```text
앞서 입력된 초기 재고 수량(아몬드봉봉 1통, 엄마는외계인 0통, 민트초코 3통)을 기억하고 있다가, 이후 근무자가 "엄마는외계인 4통, 아몬드봉봉 2통 채워놨어"라고 보고하면 기존 수량에 보충 수량을 더해서 현재 총 재고 수량을 계산해 괄호 안에 갱신해 줘.
```

### 받은 결과
- 대화가 10턴 이상 길어지고 중간에 예약 시간 변경이나 다른 질문이 끼어들면, 초기 재고 수량(`1통`)과 새로 채운 수량(`2통`)을 더하지 않고 새로 입력된 숫자(`2통`)로 덮어쓰거나 이전 턴의 숫자를 누락하는 계산 오류가 간헐적으로 발생함.

### 막힌 이유 (직접 작성)
- LLM은 텍스트 생성 모델이지 상태 값을 저장하는 데이터베이스(DB)가 아니기 때문에, 여러 턴에 걸쳐 변하는 재고 수량을 머릿속으로 누적 덧셈·뺄셈하며 유지하는 데 한계가 있었다. 프롬프트로 "이전 재고와 합산하라"고 지시해도 대화가 길어지면 문맥 창(Context) 속에서 초기 수치를 놓치거나 덮어쓰는 문제가 발생해, 정확한 재고 수량 계산은 별도의 엑셀이나 POS 시스템에 맡겨야 한다고 판단하여 미해결로 기록했다.
